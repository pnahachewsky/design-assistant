Standalone And Link-Direction Sentence Checks
Generated: 2026-03-16

Scope
- This file lists only the checks for standalone link sentences and link-direction sentences in alert rewrites.
- It does not include the other link guards such as placeholder links, adding new links, or removing links.

Main reject check
- Reject reason: fullSentenceLinksNeedLeadIn
- Purpose: reject rewritten alerts when link-direction text does not match the allowed paragraph pattern.

Where it is enforced
- src/app/views/page-assistant/services/alert-rewrite-guard.service.ts
- src/app/views/page-assistant/services/alert-rewrite-orchestrator.service.ts
- public/ai-prompts/alerts-rewrite-rules.json
- public/ai-prompts/link-writing-rules.json
- public/skills/link-writing/references/link-writing-rules.json

What currently gets rejected

1. Link-only sentence or paragraph without an allowed lead-in
- If a sentence is basically just a link, it is rejected unless it uses an allowed standalone lead-in.

2. Directional wording inside a normal sentence
- If a sentence uses wording like these before or around a link, it is rejected:
  - learn more
- This is the check that rejects patterns like:
  - "Learn more in <link>" inside a substantive sentence

3. Allowed lead-in used in a paragraph with more than one sentence
- Even if the lead-in is allowed, it is rejected when that same paragraph contains another sentence.
- Current behavior expects the link-direction paragraph to stand on its own.

Placement preference
- If a standalone link sentence or paragraph is used, the prompts now prefer it to be the last sentence and last paragraph of the alert content.
- This is prompt guidance only. It is not a hard reject in the guard.

Allowed standalone lead-ins
- Refer to:
- Learn more:
- Any lead-in starting with "Find out"
- "Learn about" is prompt guidance only and is not specially checked by the guard
- For phrasal lead-ins such as `Find out` and `Learn about`, the prompts now tell the model to let the link text complete the phrase and avoid repeating the topic noun before the anchor.

Code points to change if you want to relax these checks

Primary enforcement methods
- hasFullSentenceLinkWithoutAllowedLeadIn(...)
- isValidStandaloneLinkLeadIn(...)
- hasDirectionalLinkLeadIn(...)

What each method does
- hasFullSentenceLinkWithoutAllowedLeadIn(...)
  - parses each paragraph
  - detects whether a sentence contains a link
  - rejects link-only sentences without an allowed lead-in
  - rejects directional wording embedded inside substantive sentences
  - rejects allowed lead-ins when the paragraph has more than one sentence

- isValidStandaloneLinkLeadIn(...)
  - allows only:
    - refer to:
    - learn more:
    - any lead-in starting with find out
  - does not specially validate "learn about"

- hasDirectionalLinkLeadIn(...)
  - flags any use of:
    - learn more
  - no longer treats "refer to", "find out", or "learn about" as directional wording triggers

  - L12_lead_in_selection

If your goal is to make this less strict
- Allow more lead-in variants:
  - relax isValidStandaloneLinkLeadIn(...)
  - update L7, L11, L12 in both link-writing JSON files
  - update fullSentenceLinksNeedLeadIn in alerts-rewrite-rules.json

- Allow "refer to <link>" inside a normal sentence:
  - this is now allowed by the runtime guard
  - prompt wording has been softened to match

- Allow a lead-in paragraph to also contain another sentence:
  - remove or relax the check for allowed lead-in plus multiple sentences in hasFullSentenceLinkWithoutAllowedLeadIn(...)

- Runtime guard behavior:
  - "Find out" is no longer specially constrained by the guard beyond allowing any lead-in that starts with "Find out".
- Prompt behavior:
  - "Find out" is still specially described in the prompt files through L11_find_out_usage.
- "Learn about" is now prompt guidance only and is not specially constrained by these checks.
- Acceptable existing final standalone link sentences such as `Find out [link].` are now explicitly preserved by the rewrite prompt unless a selected issue clearly requires a change.

Important note
- Runtime enforcement is not driven only by the skill reference file.
- If you change only public/skills/link-writing/references/link-writing-rules.json, the guard code can still reject the output.
