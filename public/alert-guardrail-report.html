Alerts – Link rewriting guardrails

Summary of the rules that keep the alert rewrite flow clear, accessible, and low-risk. It focuses on what the system enforces and how decisions are made rather than on implementation details.

Conservative by design Links tightly controlled Examples cannot be copied blindly Original alert is preserved if needed

Overview

The rewrite flow is designed to improve clarity without introducing avoidable risk. At a glance, we have:

  1. Prompt rules guide the model
  2. Heuristics validate the output
  3. The system falls back safely when a rewrite is not good enough
Prompt-Based

Model guidance

The system tells the model what good output should look like. This covers tone, length, heading expectations, link-writing preferences, and example usage.

Heuristic-Managed

System enforcement

The system checks the draft itself. It can reject, retry, repair, or fall back even if the prompt already asked for the right behavior.

Mixed Control

Guided and enforced

Some important rules are handled in both layers: the prompt asks for them, and the system still validates them before accepting the rewrite.

Hard Stops

Drafts are blocked if they...

  • Return invalid alert wrapper HTML.
  • Use placeholder link tokens instead of final links.
  • Add links that were not in the original alert.
  • Drop a required link without a justified too-many-links reason.
  • Copy example wording too closely.
Retry Then Repair

Common retry-triggered issues

  • Missing heading.
  • Malformed standalone-link phrasing.
  • Placeholder links or invalid wrapper HTML.
  • Link preservation mistakes.
Safety Net

If retries still fail

  • Repair the wrapper locally.
  • Restore or remove links based on the original alert.
  • Insert a heading locally if needed.
  • Use the safest candidate or keep the original alert.

Prompt-Based

Writing guidance sent to the model

  • State what happened first, then what the user should do.
  • Use descriptive link wording rather than vague anchor text.
  • Treat examples as guidance, not copyable content.

Mixed Control

Rules guided by prompts and then validated

  • Every final alert needs a clear heading.
  • Links cannot be invented, and required links cannot disappear casually.
  • Standalone link paragraphs must use the approved pattern.
  • Good existing link endings should be preserved unless an issue requires change.
  • Example wording that is too close gets rejected and retried.

Prompt paths:

  • ai-prompts/alerts-rewrite-rules.json
  • ai-prompts/link-writing-rules.json
Heuristic-Managed

System-owned safety behavior

  • Each alert is processed independently so one failure does not block the page.
  • Issues are scoped to the relevant alert, with global issues applied wherever they matter.
  • Failed drafts are validated, retried once, repaired locally, or safely rejected.
  • The final fallback can preserve the original alert when that is safest.

No Retry Text

Purely heuristic fallback actions

Some protections happen after retries fail, without appending more prompt text.

  • Strip unexpected links when the original alert had none.
  • Restore at least one original link when one should have been kept.
  • Insert a heading locally if the model still did not provide one.
  • Rebuild a minimal valid alert wrapper.
  • Keep the safest candidate or fall back to the original alert.

Decision Flow

The end-to-end sequence from alert detection through retry, repair, and final fallback.

Expand
  1. 1
    Find the alerts and scope the issues

    Heuristic-managed. The page is scanned for alert components. Each alert gets only the issues that apply to it, plus any global issues that apply everywhere.

  2. 2
    Build a rewrite plan

    Mixed control. The system first builds a heuristic plan from the alert and its issues. In advanced mode, it can also ask the model for a more detailed planning pass before rewriting.

  3. 3
    Draft the rewrite with rule-based guidance

    Prompt-based. The rewrite step receives the alert text, the selected issues, the style rules, and any allowed example patterns. Link rules are included when the alert contains links.

  4. 4
    Validate the draft immediately

    Heuristic-managed. The system checks for missing headings, invalid structure, placeholder links, invented links, missing required links, weak standalone-link wording, and copied example text.

  5. 5
    Retry once with targeted corrections

    Mixed control. If a draft fails validation, the flow gives a short, specific prompt correction and tries again instead of accepting the first weak result.

  6. 6
    Attempt a local repair if needed

    Heuristic-managed. If the retry still falls short, the flow performs one deterministic repair pass. This can restore a required link, remove an unexpected link, rebuild a valid alert wrapper, or insert a heading.

  7. 7
    Prefer the safest final outcome

    Heuristic-managed. If the flow cannot produce a clearly safe rewrite, it does not force one. It falls back to the safest available version, which can include keeping the original alert.

  8. 8
    Patch the page alert by alert

    Heuristic-managed. Once each alert has a final version, the page is updated. Because alerts are processed independently, one difficult alert does not stop the others from being improved.

Bottom Line

The alert rewrite flow is deliberately conservative. It improves clarity and accessibility, but it does so inside clear boundaries: do not invent links, do not lose necessary links, do not borrow example wording, and do not ship an unsafe rewrite when the original alert is the safer choice.
