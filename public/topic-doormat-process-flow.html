AIDA topic doormat process

Topic doormat review and rewrite overview (in-progress)

This page summarizes how AIDA detects GCWeb topic doormats, sends structured doormat data to the issue prompt, and uses the issue output as the basis for later rewrite work.

Process summary

  1. Detect topic doormat blocks with .gc-srvinfo.
  2. Extract link text, destination, description, counts, and H2 section metadata.
  3. Run local deterministic checks for counts and predictable structure issues.
  4. Send the complete doormat set to the Topic doormats issue skill.
  5. Parse returned issue rows and fill omitted clean doormats with No issues rows.
  6. Use selected issue rows as rewrite input when rewrite support is applied.

Topic doormat review flow

The issue flow is set-based. AIDA sends all detected topic doormats together so the model can compare the complete set while AIDA keeps deterministic checks local.

Input

What AIDA sends

AIDA sends structured doormat summaries, including page order, section-local order, link text, href, description, exact character counts, and extracted H2 section metadata.

Output

What AIDA gets back

The model returns JSON issue rows grouped by doormat, plus section-level issues when the taxonomy asks for them. AIDA normalizes labels, suppresses unsupported rows, and fills missing clean doormats with No issues rows.

Section rules

H2 headings define section-local numbering for the doormat limit. Other consistency checks still compare the full supplied doormat set unless the taxonomy explicitly scopes the check to one section.

Local structure

H2 sections reset numbering

AIDA assigns each topic doormat to the nearest preceding H2 section and numbers doormats from 1 inside that section.

Limit rule

Nine doormats per section

AIDA reports too-many-doormats-in-section once as a section-level issue when an H2 section has more than 9 doormats.

Set comparison

Consistency stays set-wide

Style and consistency checks compare the complete doormat set so the model can see patterns that cross H2 sections.

What AIDA checks for

The current flow splits deterministic checks from model judgment. AIDA owns exact counts and local fallback rows; the model handles editorial and comparative judgment.

Exact character counts

AIDA provides authoritative link text and description character counts.

Doormat count limit

AIDA applies the 9-doormat limit per H2 section.

Description and link style

The model compares the complete set for meaningful style inconsistency.

Most requested duplicates

AIDA compares doormat links with Most requested links locally to identify duplicate destinations.

No issues rows

AIDA keeps every detected doormat visible, including clean items.

Fallback behaviour

If the model response is empty or invalid, AIDA builds local No issues rows.

Anne's original categories

I outlined some possible doormat pain point categories. In bold is the potential category, sub-bullets contain the more detailed issue. Let me know if this helps or if you need something else.

  • Link code issue
    • Broken link
    • Misdirected link (wrong page or wrong anchored location)
    • More than one link
  • Link name
    • Lacks clarity (must provide clear choice)
      • Must be descriptive and unique on page
    • Too long (wordy)
      • EN ideally under 35 characters (with spaces)
      • FR ideally 45 characters (with spaces)
    • Too different from destination page title
      • Does not need to be exact match of destination page title, but should convey similar idea
  • Repeat link
    • Don't repeat links in Most requested
  • Description lacks clarity (unclear)
    • Missing needed information (content gap)
  • Description too long (too wordy)
    • EN should be under 90 characters?
    • FR under 120 characters?
  • Description has incorrect style (not sure of Marvin's wording on this)
    • Action verbs that summarize what can be done on the page
    • list of keywords that summarize information on the page
    • list of tasks that can be accomplished on the page
    • (We have examples of the style options in the UCDG Doormats – GCWeb design system)
  • Description formatting
    • Don't use "and" before the last item in the list
    • Don't use icons or images
    • No special formatting (bold, italics, bullets)
    • Capitalize the letter of the first word
    • Use commas to separate listed items or phrase
    • Do not put any punctuation at the end
    • No links in description
  • Enhancement label
    • Only for a recent change (e.g. info label "New", Danger label "Closed")
  • Choice of doormats
    • Missing a needed doormat
    • Extra doormat that is not needed (badly chosen)
  • Wrong doormat order (prioritize most visited info and services).

Runtime code paths

Implementation files that run detection, prompt composition, issue calls, parsing, deterministic rows, and table display.

  • Coordinates the guidance table, expands the Topic doormat row, and displays issue groups and status. src/app/views/page-assistant/components/problems/component-guidance/component-guidance.component.ts
  • Parses page HTML into doormat summaries, section metadata, language signals, and Most requested link context. src/app/views/page-assistant/services/topic-doormat-extractor.service.ts
  • Composes the issue request, parses model JSON, applies deterministic issue rows, and resolves final rows. src/app/views/page-assistant/services/topic-doormat-issue-analysis.service.ts
  • Calls the selected model, rotates through fallbacks, and repairs invalid JSON responses. src/app/views/page-assistant/services/topic-doormat-model-client.service.ts
  • Groups issue rows, builds category summaries, and maps issues to the displayed health state. src/app/views/page-assistant/services/topic-doormat-presenter.service.ts
  • Defines shared Topic doormat interfaces used by the component and services. src/app/views/page-assistant/services/topic-doormat.types.ts
  • Loads the active AIDA skill files, references, and schemas used to build the model prompt. src/app/views/page-assistant/services/skill-manager.service.ts

Bottom line: AIDA evaluates Topic doormats as a complete set, uses H2 sections only where the rules require section-local structure, and keeps the prompt files linked above as the active source of issue and rewrite guidance.
