AIDA topic doormat process

Topic doormat review and rewrite overview (in-progress)

This page summarizes how AIDA detects GCWeb topic doormats, sends structured doormat data to the issue prompt, and uses the issue output as the basis for later rewrite work.

Process summary

  1. Detect topic doormat blocks with .gc-srvinfo.
  2. Extract link text, destination, description, counts, and H2 section metadata.
  3. Run local deterministic checks for counts and predictable structure issues.
  4. Send the complete doormat set to the Topic doormats issue skill.
  5. Parse returned issue rows and fill omitted clean doormats with No issues rows.
  6. Use selected issue rows as rewrite input when rewrite support is applied.

Topic doormat review flow

The issue flow is set-based. AIDA sends all detected topic doormats together so the model can compare the complete set while AIDA keeps deterministic checks local.

Input

What AIDA sends

AIDA sends structured doormat summaries, including page order, section-local order, link text, href, description, exact character counts, and extracted H2 section metadata.

Output

What AIDA gets back

The model returns JSON issue rows grouped by doormat, plus section-level issues when the taxonomy asks for them. AIDA normalizes labels, suppresses unsupported rows, and fills missing clean doormats with No issues rows.

Section rules

H2 headings define section-local numbering for the doormat limit. Other consistency checks still compare the full supplied doormat set unless the taxonomy explicitly scopes the check to one section.

Local structure

H2 sections reset numbering

AIDA assigns each topic doormat to the nearest preceding H2 section and numbers doormats from 1 inside that section.

Limit rule

Nine doormats per section

AIDA reports too-many-doormats-in-section once as a section-level issue when an H2 section has more than 9 doormats.

Set comparison

Consistency stays set-wide

Style and consistency checks compare the complete doormat set so the model can see patterns that cross H2 sections.

What AIDA checks for

The current flow splits deterministic checks from model judgment. AIDA owns exact counts and local fallback rows; the model handles editorial and comparative judgment.

Exact character counts

AIDA provides authoritative link text and description character counts.

Doormat count limit

AIDA applies the 9-doormat limit per H2 section.

Description and link style

The model compares the complete set for meaningful style inconsistency.

Most requested duplicates

AIDA sends Most requested links so the model can identify duplicate destinations.

No issues rows

AIDA keeps every detected doormat visible, including clean items.

Fallback behaviour

If the model response is empty or invalid, AIDA builds local No issues rows.
