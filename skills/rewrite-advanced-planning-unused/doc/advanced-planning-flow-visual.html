AIDA advanced planning flow

Advanced planning adds a separate model call before alert rewriting. That first call creates a structured plan, and AIDA uses the plan to choose examples and focus the final rewrite request.

One-sentence explanation

Advanced planning helps AIDA decide what kind of rewrite is needed before it writes. The planner classifies the alert, creates rewrite directives, and gives AIDA better labels for selecting relevant examples.

Where it fits

AIDA always processes alert rewrites one alert at a time. With planning off, it uses a local heuristic plan. With planning on, it asks the model to refine that plan before the rewrite prompt is built.

flowchart TD A[Selected alert issues] --> B[Find reportable alert elements] B --> C[For each alert] C --> D[Build local heuristic plan] D --> E{Advanced planning on?} E -->|No| F[Use heuristic plan] E -->|Yes| G[Planning model call] G --> H[Structured model plan] F --> I[Select examples] H --> I I --> J[Build rewrite payload] J --> K[Rewrite model call] K --> L[Parse JSON and HTML] L --> M[Guard checks, retry, or local repair] M --> N[Patch final alert into page HTML]

Example alert

This example is useful because the alert has a real issue: it says something is unavailable, but the next step is weak and the alert has no heading.

Original alert 
<div class="alert alert-warning">
  <p>
    Some CRA services are unavailable. For more information,
    visit <a href="/en/revenue-agency/services/e-services/cra-login-services.html">CRA sign-in services</a>.
  </p>
</div>
Selected issue 
{
  "alertIndex": 1,
  "category": "Missing next step",
  "severity": "High",
  "description": "The alert says services are unavailable but does not clearly tell users what to do next.",
  "recommendation": "Add a clear next step and a short heading."
}

Payload difference

The clearest difference is the plan inside the rewrite payload. Planning off sends the model a simpler plan with no rewrite operations. Planning on sends a richer plan with directives.

Advanced planning off

Rewrite payload uses a simpler plan

{
  "mode": "heuristic-planning",
  "plan": {
    "alertType": "warning",
    "domainTags": ["service"],
    "purposeTags": ["action-required"],
    "criteriaMatched": ["C1_missing_next_step"],
    "directives": []
  },
  "originalHeading": "",
  "originalAlertText": "Some CRA services are unavailable. For more information, visit CRA sign-in services.",
  "linkManifest": {
    "count": 1,
    "hasLinks": true,
    "mustPreserveAtLeastOne": true
  }
}
Advanced planning on

Rewrite payload uses a model-generated plan

{
  "mode": "model-planning",
  "plan": {
    "alertType": "warning",
    "domainTags": ["cra-services", "account-access"],
    "purposeTags": [
      "service-delay",
      "action-required",
      "missing-heading",
      "standalone-action-link"
    ],
    "criteriaMatched": ["C1_missing_next_step"],
    "directives": [
      { "op": "add_heading" },
      { "op": "add_next_step" },
      { "op": "preserve_tone" }
    ]
  },
  "originalHeading": "",
  "originalAlertText": "Some CRA services are unavailable. For more information, visit CRA sign-in services.",
  "linkManifest": {
    "count": 1,
    "hasLinks": true,
    "mustPreserveAtLeastOne": true
  }
}
What directives means: the directives array is the structured rewrite strategy. It tells the rewrite model what operations to perform, such as adding a heading, adding a next step, simplifying jargon, limiting links, or preserving tone.

The planning call

When Advanced planning is on, AIDA sends a small planning payload before the rewrite request. The planner does not write HTML. It returns classification tags and directives.

Planning request 
{
  "alertText": "Some CRA services are unavailable. For more information, visit CRA sign-in services.",
  "alertType": "warning",
  "signals": {
    "hasHeading": false,
    "hasLink": true,
    "linkCount": 1,
    "wordCount": 11
  },
  "issues": [
    {
      "category": "Missing next step",
      "severity": "High",
      "descriptionSnippet": "The alert says services are unavailable but does not clearly tell users what to do next."
    }
  ]
}
Planning response 
{
  "alertType": "warning",
  "domainTags": ["cra-services", "account-access"],
  "purposeTags": [
    "service-delay",
    "action-required",
    "missing-heading",
    "standalone-action-link"
  ],
  "criteriaMatched": ["C1_missing_next_step"],
  "directives": [
    { "op": "add_heading" },
    { "op": "add_next_step" },
    { "op": "preserve_tone" }
  ]
}

How examples are selected

AIDA uses the plan labels to choose examples. Advanced planning changes the labels, so it can change which examples are considered the best match.

Planning off

Available labels missing next step, action required, service
↓
Best match generic missing next-step example
↓
Selected example ex-001

Planning on

Available labels service delay, account access, standalone action link, missing heading
↓
Best match service-delay alert with final action link
↓
Selected examples ex-014 + ex-001
Planning off

Fewer labels, broader match

{
  "criteriaMatched": ["C1_missing_next_step"],
  "purposeTags": ["action-required"],
  "domainTags": ["service"]
}
Selected examples:
["ex-001"]

This may find a generic missing-next-step example, but it has less information about the alert's actual job.

Planning on

More labels, more specific match

{
  "criteriaMatched": ["C1_missing_next_step"],
  "purposeTags": [
    "service-delay",
    "action-required",
    "standalone-action-link"
  ],
  "domainTags": ["cra-services", "account-access"]
}
Selected examples:
["ex-014", "ex-001"]

This can match a service-delay example with the right link pattern before falling back to a generic example.

Why we want this step

  • It separates diagnosis from writing. The first call decides the rewrite strategy; the second call writes the final alert.
  • It improves example selection. AIDA can match examples by the alert's purpose, not only by a broad issue category.
  • It makes the rewrite request more specific. Directives turn the plan into concrete operations like add a heading, add a next step, or preserve tone.
  • It helps with similar-looking issues. Two alerts can both have a missing next step, but one may be a service outage, one a fraud warning, and one a policy caveat.
Team summary: Advanced planning gives AIDA a better intent map before it rewrites. That map improves example matching and gives the rewrite model a clearer job to do.
